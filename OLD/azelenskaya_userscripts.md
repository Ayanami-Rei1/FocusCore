## [ Сценарий 1 - Подключение внешней видеокамеры ]

1. Пользователь запускает приложение FocusCore на своем ПК.
2. Пользователь переходит в раздел "Настройки оборудования" в главном меню.
3. Система сканирует порты и выводит выпадающий список всех подключенных камер.
4. Пользователь выбирает нужную камеру из списка.
5. Пользователь нажимает кнопку "Проверка сигнала".
6. Если камера занята другим приложением, система выводит сообщение об ошибке и просит освободить устройство.
7. Если подключение успешно, система выводит в небольшом окне тестовое видео.
8. Пользователь нажимает кнопку "Применить и сохранить".
9. Система подтверждает выбор и возвращает пользователя на главный экран.

## [ Сценарий 2 - Настройка порога вовлеченности ]

1. Пользователь переходит в раздел "Параметры анализа".
2. Пользователь находит ползунок "Критический порог вовлеченности (в процентах)".
3. Пользователь сдвигает ползунок на нужное значение (например, 40%).
4. Пользователь включает функцию "Фиксировать аудио при падении внимания ниже порога".
5. Если микрофон не обнаружен, система выводит предупреждение о невозможности записи звука.
6. Пользователь выбирает системный микрофон из предложенного списка.
7. Пользователь нажимает кнопку "Сохранить параметры".
8. Система применяет настройки для будущей сессии анализа.

## [ Сценарий 3 - Управление записью лекции ]

1. Пользователь на главном экране нажимает большую кнопку "Начать лекцию".
2. Система запускает видеопоток и начинает фоновый инференс модели.
3. Система выводит на экран таймер и текущий статус "Анализ идет".
4. В середине лекции пользователь нажимает кнопку "Пауза" (например, во время перерыва).
5. Система приостанавливает обработку кадров и запись метрик, меняя статус на "Пауза".
6. Пользователь нажимает кнопку "Продолжить" для возобновления работы.
7. По окончании пары пользователь нажимает кнопку "Завершить лекцию".
8. Система останавливает видеопоток, сохраняет собранный массив данных о вовлеченности в локальную базу данных и переводит пользователя к экрану генерации отчета.

## [ Сценарий 4 - Мониторинг дашборда в реальном времени ]

1. Пользователь запускает процесс анализа лекции.
2. Пользователь сворачивает окно с видео, оставляя поверх других окон компактный виджет дашборда.
3. Система рассчитывает коллективную вовлеченность каждые N секунд.
4. Система отображает текущий уровень вовлеченности в виде цветового индикатора и числа (например 85%).
5. Если вовлеченность падает ниже заданного порога, индикатор окрашивается в красный цвет.
6. Пользователь кликает на индикатор, чтобы развернуть график последних 5 минут.
7. Пользователь нажимает "Свернуть", чтобы индикатор снова стал компактным и не мешал показу презентации.
8. При завершении сессии виджет автоматически закрывается.

## [ Сценарий 5 - Генерация структурированного отчета ]

1. После завершения сессии пользователь переходит во вкладку "Отчеты".
2. Пользователь выбирает только что завершенную сессию из списка.
3. Система генерирует график зависимости вовлеченности от времени (таймлайн).
4. Если за время лекции не было собрано данных (ошибка камеры), система выводит уведомление "Недостаточно данных для генерации отчета".
5. Пользователь нажимает кнопку "Экспорт в PDF".
6. Система открывает диалоговое окно выбора директории для сохранения.
7. Пользователь выбирает папку и нажимает "Сохранить".
8. Система сохраняет файл и предлагает открыть его для просмотра.

## [ Сценарий 6 - Просмотр моментов критического падения внимания ]

1. Пользователь открывает детализацию отчета прошедшей лекции.
2. Пользователь переходит в раздел "Критические моменты".
3. Система отображает список временных меток (например, 14:20 - 14:25), где вовлеченность была ниже порога.
4. Пользователь нажимает иконку "Воспроизвести аудио" рядом с первой меткой.
5. Если аудио не было записано (настройка была выключена), система выводит сообщение "Аудиозапись для данного фрагмента отсутствует".
6. Если аудио есть, система воспроизводит сохраненный фрагмент через динамики ПК.
7. Пользователь прослушивает фрагмент, чтобы понять, что он говорил в тот момент.
8. Пользователь нажимает кнопку "Добавить комментарий" к этому таймкоду.
9. Пользователь вводит текст (например, "Тема оказалась слишком сложной, нужно добавить слайд") и сохраняет его.

## [ Сценарий 7 - Управление историей сессий ]

1. Пользователь открывает вкладку "История сессий".
2. Система выводит таблицу со списком всех прошлых лекций (Дата, Длительность, Средняя вовлеченность).
3. Пользователь использует строку поиска для фильтрации сессий по дате.
4. Пользователь выделяет галочками несколько старых сессий, которые больше не нужны.
5. Пользователь нажимает кнопку "Удалить выбранное".
6. Система запрашивает подтверждение: "Вы уверены, что хотите безвозвратно удалить эти данные?".
7. Если пользователь нажимает "Отмена", данные остаются в таблице.
8. Если "Удалить", система стирает данные из локальной БД и обновляет таблицу на экране.

## [ Сценарий 8 — Управление приватностью и очистка хранилища ]

1. Пользователь заходит в настройки в раздел «Данные и приватность».
2. Система подтверждает, что исходный видеопоток не сохраняется на диск согласно архитектуре ПО.
3. Пользователь активирует функцию «Автоматическое удаление аудио-фрагментов».
4. Пользователь устанавливает срок хранения (например, «Удалять через 14 дней»).
5. Система предупреждает, что удаленные аудио-файлы нельзя будет восстановить.
6. Пользователь нажимает кнопку «Очистить кэш сейчас» для немедленного удаления старых данных.
7. Система рассчитывает объем освобожденного места и обновляет статус хранилища.
8. Пользователь закрывает настройки, подтверждая новую политику хранения.

## [ Сценарий 9 - Диагностика и решение аппаратных проблем ]

1. Пользователь нажимает кнопку начала лекции.
2. Система фиксирует недостаток оперативной памяти (менее 1 ГБ свободно).
3. Система приостанавливает запуск инференса.
4. Система выводит на экран модальное окно: "Критическая нехватка ОЗУ. Пожалуйста, закройте неиспользуемые программы".
5. Пользователь закрывает тяжелые вкладки в браузере и освобождает память.
6. Пользователь нажимает в модальном окне кнопку "Повторить проверку".
7. Система успешно проходит проверку ресурсов.
8. Система начинает запись и анализ лекции.
